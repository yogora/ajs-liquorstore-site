# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static marketing site for AJ's Beer, Wine & Spirits, a liquor store in Carterville, IL. Plain HTML/CSS, no build step, no package manager, no JavaScript framework — but as of `js/store-hours.js` (see **Client-side JavaScript**), no longer a fully JS-free site; that one small vanilla-JS file is loaded on every page for a live open/closed status. Hosted on Netlify, which auto-deploys on every push to `main` (no CI config in this repo — Netlify is configured externally via its own dashboard/GitHub integration).

## Commands

There is no build, lint, or test tooling in this repo — it's hand-authored static HTML/CSS. To preview locally, open any `.html` file directly in a browser, or serve the directory with any static file server (no server-side logic, so anything works: `npx serve`, VS Code Live Server, etc.).

## Architecture

**Multi-page, no templating.** Every page is a standalone `.html` file at the repo root that duplicates the same `<head>` boilerplate, the status strip, `<header>` (nav), `<footer>`, the sticky mobile action bar, and the closing `<script src="js/store-hours.js" defer>` verbatim. There is no shared partial/include mechanism — when changing any of those, **the edit must be repeated identically across all 7 pages**: `index.html`, `visit-us.html`, `specials.html`, `spirits.html`, `beer.html`, `ready-to-drink.html`, `wine.html`. Category page filenames are flat (not under a `/products/` subdirectory), so all internal links and asset paths (`css/styles.css`, `js/...`, `assets/...`) are relative to the repo root on every page. `about.html` was retired and folded into `visit-us.html` (see **Visit Us page**), and `deals.html` was renamed `specials.html` (see **Specials page**) — the site no longer uses "Deals" anywhere in its own copy. A root `_redirects` file 301s both old URLs (`/about.html` → `/visit-us.html`, `/deals.html` → `/specials.html`) for Netlify.

**One global stylesheet.** All styles live in `css/styles.css`, organized into commented sections (Store status strip, Header, Nav dropdown, Hero, Category CTAs, This Week In The Store, Stop In Today, Highlights, Brands, Specials page, Page header, Placeholder sections, Visit Us page, Mobile action bar, Footer, Responsive) roughly matching page section order. There's no CSS scoping convention beyond descriptive class names — new sections should follow the existing pattern of one comment banner + a handful of classes per section, added near thematically related rules rather than appended at the end.

**Design tokens** are CSS custom properties in `:root` (`--red`, `--ink`, `--off-white`, `--white`, `--maroon` (deep oxblood, used for the Visit Us CTA panel — see **Product category pages**), `--font-display` (Archivo), `--font-body` (Inter), `--max-width`). Always reuse these instead of hardcoding colors/fonts. Fonts load from Google Fonts via `<link>` in each page's `<head>`.

**Nav dropdown is CSS-only** (the site's one JS file, `js/store-hours.js`, has nothing to do with navigation — see **Client-side JavaScript**). The "Products" menu uses a native `<details>`/`<summary>` element (`.nav-dropdown` / `.nav-dropdown-toggle` / `.nav-dropdown-menu`) for open/close, styled differently per breakpoint:
- Desktop (`@media (min-width: 701px)`): floating popover, shown on `:hover` or the native `[open]` state, absolutely positioned and centered under the toggle via `transform: translateX(-50%)`.
- Mobile (`@media (max-width: 700px)`): inline accordion, shown via `display: none/flex` toggled by `[open]`.

These two behaviors are kept in **separate, non-overlapping media queries** deliberately — an earlier bug came from a single global rule setting `transform` on `[open]` that leaked into mobile and visually displaced the menu while leaving it clickable in its original (empty-looking) position. Don't reintroduce shared position/transform rules for `.nav-dropdown-menu` across both breakpoints.

**Mobile nav toggle (hamburger) is also JS-free**, using the checkbox-hack pattern: a hidden `<input type="checkbox" id="nav-toggle">` + `<label for="nav-toggle">` with three `<span>` bars, toggled via `:checked ~` sibling selectors. This markup block must stay identical across all 7 pages' headers.

**Header additions on every page**, beyond the logo/nav:
- **Store status strip** (`.store-status-strip`, a full-width band above `<header>`): a `<p id="store-status">` whose text is filled in live by `js/store-hours.js` ("Open today until 10:00 PM", etc.) — the markup's own text is just the no-JS fallback. On every page except `visit-us.html` itself, the script also appends a "Visit Us" link.
- **Get Directions nav button** (`.nav-directions-btn`, last item inside `.site-nav`): a `.btn.btn-primary` styled to sit inline with the plain nav links. Hidden at `max-width: 700px` — the sticky mobile action bar's own Directions link takes over there instead. Because it's the last child of `.site-nav`, the mobile dropdown's "no border on the last link" rule (`.site-nav > a:last-child`) is duplicated onto `:nth-last-child(2)` so the link before it (now the visually-last one on mobile) also loses its trailing border.
- **Sticky mobile action bar** (`.mobile-action-bar`, a `<nav>` placed after `<footer>`): fixed to the bottom of the viewport, shown only at `max-width: 700px` (`display: none` otherwise). Three actions — Directions (maps link), Call (`tel:`), Hours (`visit-us.html`) — each an inline hand-drawn SVG icon over a short label. `body` gets `padding-bottom: 60px` at that same breakpoint so the bar never covers the footer's own content.

**Client-side JavaScript** (`js/store-hours.js`, loaded with `defer` on every page — the only JS in the site): computes a live open/closed status from two hard-coded data structures at the top of the file:
- `WEEKLY_HOURS` — the regular Mon–Sun schedule. Keep this in sync with the hours hard-coded in every footer and on `visit-us.html`; the script never builds or replaces that static hours HTML (Google reads static text more reliably, and it's what the `LiquorStore` JSON-LD should match) — it only computes a status message from the same numbers.
- `HOLIDAY_OVERRIDES` — keyed by `"YYYY-MM-DD"` Central-time date strings, currently empty. **This is the main recurring maintenance task**: add an entry before Thanksgiving, Christmas, New Year's, etc. and update the Google Business Profile at the same time — showing "Open now" when the store is actually closed does more damage than showing no status at all. The "opens tomorrow" message always uses `WEEKLY_HOURS` for the next day and does not check overrides for that date; a comment in the file calls this out.

The script always checks the time in Carterville (`America/Chicago`) via two `Intl.DateTimeFormat` calls (never the visitor's own device time zone), then writes the result into `#store-status`. On `visit-us.html`, it also adds an `.is-today` class to whichever `.full-hours-list li[data-hours-day]` matches the current day.

**Hero image** (`index.html` only): `assets/hero-exterior.png` is pre-cropped (top ~18% of sky trimmed from the original photo) so the storefront and sign dominate the frame rather than empty sky. The storefront sign sits in a fixed band of that image, so the `<h1>` (`.hero-headline`) and the CTA button are deliberately split to the top and bottom of `.hero-inner` (a column flex with `justify-content: space-between`) instead of stacked together — this keeps both clear of the sign at every viewport width instead of overlapping it. Two gradients layer into the `.hero` background (top-down for the headline, bottom-up for the button), leaving the middle — where the sign is — clear of any darkening overlay. `background-position` (`31% 18%`) is tuned per-axis for two different fit regimes this wide image produces depending on viewport shape: at narrow/tall (mobile) widths the image is height-bound (its full height always shows, so only the X value matters, keeping the full sign width in frame); at wide/short (desktop) widths it's width-bound (only the Y value matters, framing the sign vertically). A single `.hero` `min-height: 440px` is now used across all breakpoints — no separate mobile override — since the split top/bottom layout no longer needs extra mobile height to avoid overlap. If the source photo or crop ever changes, re-derive both the position values and this min-height rather than assuming they still hold.

**Category CTAs** (`.category-cta` / `.category-grid` / `.category-card`, `index.html` only): 4 compact, one-word tiles (Spirits, Beer, Ready-to-Drink, Wine) — just an `<h3>` inside a `--red`-bordered, rounded `<a>`, no blurb or "Shop X →" link text. `.category-grid` is `repeat(4, 1fr)` on desktop but deliberately stays at `repeat(2, 1fr)` all the way down through the `max-width: 600px` query (not `1fr`) so the tiles form a 2x2 grid on mobile instead of a tall single-column stack.

**Homepage sections** (`index.html` only), in order below the category CTAs:
- **This Week In The Store** (`.this-week`): white section background with 3 `.week-card` teaser cards on the cream `--off-white` background. Each card is wrapped in `<!-- This week card N --> … <!-- End this week card N -->` comments, mirroring the `specials.html` on-sale-card convention, with bracketed `[Special Name]` / `$[XX.99]` placeholders for the site owner to fill in with real, current specials — keep these roughly in sync with what's live on `specials.html`. A "See All Specials & New Arrivals" link points to `specials.html`.
- **Stop In Today** (`.stop-in`): cream `--off-white` background, two-column layout. Left side has the address and hours (kept in sync with the footer's — update both if either changes) plus two CTAs: `.btn-primary` (red, "Get Directions") and `.btn-ghost-ink` (a third button variant — transparent background, `--ink` border/text — for "Call"). Right side is the shared `.map-embed` component (see **Visit Us page**) — a real Google Maps `<iframe>`, not a placeholder; `.stop-in-map` just overrides its aspect ratio for this grid.
- **Highlights** (`.highlights`): white background, 4 `.highlight-card`s (Deep Selection, Always Cold, Lottery & Essentials, Local & Friendly), each a hand-drawn inline SVG icon inside a `.highlight-icon` circle plus a one-line blurb. No icon library or JS — icons are authored inline like the existing `.nav-caret` SVG.
- **Brands** (`.brands`): cream `--off-white` section containing a `.brands-panel` — a rounded, `--red`-bordered card using the `--maroon` token, the same contained-panel technique as the Visit Us CTA on category pages — so it reads as its own element rather than blending into the black footer directly below it. Lists 6–7 carried brand names as plain text in `.brand-list`. Swap the list as inventory/featured brands change.

**Content patterns already established, reuse rather than inventing new ones:**
- `.page-header` / `.page-header-sub` — the title band used by Visit Us, Specials, and all 4 category pages.
- `.placeholder-section` / `.placeholder-inner` — the "coming soon" body originally used by all 4 category pages before they were built out. No page uses it anymore, but the pattern stays in `css/styles.css` in case a future category page starts from scratch.
- `.btn` / `.btn-primary` / `.btn-ghost` — the two original button styles, plus `.btn-ghost-ink` (transparent, `--ink` border/text) added for the homepage's "Call" CTA.
- On-sale cards on `specials.html` (`.on-sale-card`) are each wrapped in HTML comments (`<!-- On sale card N: ... -->` / `<!-- End on sale card N -->`) since the site owner edits these regularly with real product data; preserve that comment structure when adding/editing.

**Product category pages.** All four — `spirits.html`, `beer.html`, `wine.html`, `ready-to-drink.html` — share the same structure, with only category names, subcategories, and products swapped in. `spirits.html` was the original template; use any of the four as a reference. Each page is built from these pieces, in order:
- **Breadcrumb** (`.breadcrumb` / `.breadcrumb-list`): a `Home / Products / <Category>` trail above the `<h1>` inside `.page-header`. "Products" is plain text (no dedicated products landing page exists); only "Home" links out. The current page gets `aria-current="page"` on its `<li>`, not a link.
- **Jump nav** (`.jump-nav` / `.jump-nav-list` / `.jump-pill`): a pill-style row of real `<a href="#anchor">` links (no JS) to each subcategory section, placed right after `.page-header`.
- **Subcategory sections** (`.product-section`, one per subcategory, each with a semantic `id` like `#bourbon` — not `#section-1`, since these double as deep links). Each has one `<h2>` (never skip to `<h3>` without it), a one-sentence blurb in `.product-section-intro`, and a `.product-grid` of `.product-card`s (5 per subcategory on `spirits.html`).
- **Product cards** (`.product-card`), each wrapped in `<!-- Product card: <Subcategory> N --> ... <!-- End product card: <Subcategory> N -->` comments, mirroring the `specials.html` on-sale-card convention so the site owner can find and swap individual products easily. Structure: `.product-card-image` (a fixed-aspect-ratio div with a neutral background-color fallback so a missing photo never breaks layout or shows a broken-image icon) containing an `<img>`, then `.product-card-name` (`<h3>`) and `.product-card-meta` (category/size line). No pricing field — this site doesn't show prices on category pages.
- **Product images**: point every `<img src>` at `assets/products/<slug>.jpg` even before the file exists, using a consistent kebab-case naming convention: `<category>-<brand-and-product>-<size>.jpg` (e.g. `assets/products/bourbon-makers-mark-750ml.jpg`, `assets/products/vodka-smirnoff-no21-1-75l.jpg` — periods in sizes like `1.75L` become `1-75l`). Write real, descriptive `alt` text (brand + product + size) now; dropping a correctly named file into `assets/products/` later requires no HTML changes.
- **Badge** (`.product-badge`): a single optional `<span class="product-badge">Label</span>` as the first child of a `.product-card`, positioned absolute so it overlays the card's top-right corner (same technique as `.on-sale-badge` on `specials.html`). Reused for all badge copy ("Staff Pick", "Local Favorite", "New Arrival", "Everyday Value") — it's one class, not one per label; just add or remove the `<span>` per product. Use on only 1–2 cards per subcategory section.
- **"Not exhaustive" messaging**: these pages show a sample of in-store products, not the full inventory, so the intro callout below the H1 and the closing CTA both explicitly say so and point people to call or stop in for anything not pictured — don't let either read like a complete catalog.
- **Page-header callout** (`.page-header-callout`): wraps the `.page-header-sub` paragraph in a rounded, `--red`-bordered box on the page's cream `--off-white` background, sitting right below the `<h1>`. The copy always opens with "This page is just a sample of what we carry." before the category-specific sentence. Deliberately styled differently from the Visit Us CTA at the bottom (cream + red outline here vs. the solid `--maroon` panel there) so the two don't read as the same component.
- **Visit Us CTA** (`.visit-cta`): a standalone callout before `</main>`, deliberately *not* styled like the footer it sits above — the outer `.visit-cta` section keeps the page's cream `--off-white` background (not `--ink`), and the actual content lives in a `.visit-cta-panel`: a rounded, `--red`-bordered card using the dedicated `--maroon` token (a deep oxblood, distinct from both `--ink` and `--off-white`) so it visually pops as its own element instead of merging into the black footer below. Inside `.visit-cta-panel` is `.visit-cta-inner`, a single centered column: a headline + `.visit-cta-desc` blurb reiterating that the page is just a sample of what's carried in-store, plus `.visit-cta-actions` with a `tel:` call button and a "Get Directions" link (reusing `.btn`/`.btn-primary`/`.btn-ghost`). No hours/address here — that lives in the footer immediately below; keep the two in sync if hours or location ever change.
- **Schema.org markup**: deliberately not added to product cards yet — there's no real price/availability data, and structured data on placeholder products risks Search Console errors. Add `Product` schema once real inventory (with prices) exists. (Separately, `index.html` carries `LiquorStore` JSON-LD in `<head>` with name/address/phone/hours — that's store-level data, not product data, so it isn't blocked by the same concern.)
- **"Ready-to-Drink" is always hyphenated** in visible copy (nav label, `<h1>`, breadcrumb, homepage card) — not "Ready to Drink". The filename `ready-to-drink.html` was already hyphenated; the visible label was standardized to match.

**Visit Us page** (`visit-us.html`) replaced the old `about.html` and the nav's `#location` anchor — it's the single destination for "should I go there?" and the page the Google Business Profile's website link should point to, so it's built to answer that completely on its own:
- **Visit Info** (`.visit-info`, cream `--off-white` background): a single centered `.visit-info-inner` column (not the two-column grid the homepage's Stop In Today uses) containing, in order: an `<h2>Hours</h2>` and `.full-hours-list` (one `<li data-hours-day="monday">` etc. per day, so `js/store-hours.js` can add `.is-today` to exactly one row); address; the shared `.map-embed` real Google Maps iframe (also used by the homepage's Stop In Today — no API key needed, just `https://maps.google.com/maps?q=<address>&output=embed`); `.visit-info-actions` with Get Directions (`.btn-primary`) and Call (`.btn-ghost-ink`); and a short Parking & Drive-Thru note.
- **About AJ's, folded in from the retired about.html**: `.visit-story` (centered intro blurb, with a `.visit-divider` accent bar above it), `.visit-gallery` (one wide `.visit-gallery-feature` photo plus a `.visit-gallery-grid` of 4 `.visit-gallery-item`s — `assets/gallery/store-1.jpg` through `store-5.jpg`), then a single `.visit-feature` section for Food Trucks. (There used to be a second `.visit-feature` for Drive-Thru; that content was folded into the Visit Info blurb instead, so `.visit-feature` no longer needs the old `:last-of-type` border trick — there's only one instance now.)
- Carries its own `LiquorStore` JSON-LD (same shape as `index.html`'s), and is the header nav's `Visit Us` link plus the sticky mobile action bar's `Hours` link on every other page.

**Specials page** (`specials.html`, replaced `deals.html`) uses customer-facing section names, not internal ones, and is deliberately just one page with (up to) three sections rather than a `deal-of-week` hero plus a separate grid plus a separate recurring-specials section the way the old page did. Order: New Arrivals, On Sale, then the signup:
- **New Arrivals** (`.new-arrivals`, `id="new-arrivals"`), first on the page. While there's only one new arrival, it's a single full-width `.arrival-feature` card (`<article>`, wrapped in `<!-- New arrival feature: <Name> --> … <!-- End new arrival feature -->`): image left (`.arrival-feature-image`, white background so white-backdrop bottle shots blend in, `object-fit: contain` so they never crop — crop product photos tight to the bottle first, or it renders small) and body right, with a "New Arrival" `.arrival-feature-badge` (inline, not the absolute-positioned `.product-badge`), name, meta line, a brand-voice description, a `<dl class="arrival-feature-notes">` of Nose/Palate/Finish tasting notes, and `.arrival-feature-price` (nothing below the price). It stacks to one column at `max-width: 700px`. **This card shows a price** — the "no pricing" rule is for the product category pages only. Currently Weller Antique 107 ($99.99, image `assets/products/bourbon-weller-antique-107-750ml.jpg`; copy paraphrased from Buffalo Trace's product page). Once several new arrivals run at once, switch to a `.new-arrivals-grid` of `.product-card`s (the CSS is kept for this), each with a "New Arrival" `.product-badge`, matching the category pages.
- **On Sale** (`.on-sale`, `id="on-sale"`): discounted products — kept "plain and scannable" per the site owner's own framing, so it's one `.on-sale-grid` of 6 `.on-sale-card`s (badge/image/name/meta/price/note), each wrapped in `<!-- On sale card N --> … <!-- End on sale card N -->` comments. Still bracketed placeholders until the site owner fills them in. (The old "Standing Weekly Specials" subsection — Wine Wednesday etc. — was removed along with its `.recurring-*` CSS.)
- **Staff Picks** — hidden on purpose until the site owner is actually hand-picking items (an honest "Featured" would be the fallback name if that's not true). Currently just an HTML comment after On Sale explaining how to add it later: a `.product-card` grid, each card with a "Staff Pick" `.product-badge`, section `id="staff-picks"`.
- **Special Alert Signup** (`.special-alert` / `.special-alert-panel` / `.special-alert-embed`, renamed from `.deal-alert*`): the same Zite embed as before — see **Third-party embed**. Its own generated copy still says "Never Miss A Deal" since that text lives inside the externally-generated snippet, not in this repo; that's a known, accepted inconsistency until the snippet is regenerated externally.
- Page `<h1>` is "Specials & New Arrivals"; the intro line under it should stay in brand voice and avoid keyword-stacking (see the Hero H1 precedent).

**Third-party embed**: `specials.html` embeds a Zite (Fillout) email signup form via a snippet the site owner generated externally (`data-zite-id="uqk9ijddp8"` + `server.fillout.com` script). Treat that snippet as opaque/do-not-edit; if its rendered size or behavior needs adjusting, override it with CSS on `.special-alert-embed` (see the existing `height` override there) rather than modifying the snippet's own attributes.

## Deployment

Pushing to `main` on GitHub (`yogora/ajs-liquorstore-site`) triggers a Netlify deploy automatically. There are no feature branches or PR workflow in use — changes are committed and pushed directly to `main`.
